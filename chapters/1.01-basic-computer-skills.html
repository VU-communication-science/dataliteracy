1.1 Basic Computer Skills

The file system, paths, and general computer habits.

Basic computer skills are the foundation everything else in this book builds on. Most of you will already have plenty of experience using a computer, but there can still be gaps in your understanding, especially around things like how the file system actually works. This chapter gives a quick overview of the key skills worth having. We highly recommend reading through it once to see where you stand.

1.1.1 Files and folders

Everything on your computer — documents, photos, programs, and (soon) your data files — is stored as a file, and files are organised into folders (also called directories). This is called the file system, and most people navigate it using a file explorer. The following example is for MacOS, but it works the same on Windows and Linux.

You might already have a good intuition for how to use a file explorer. However, to effectively work with data, and responsibly handle sensitive information, you need a good understand how files and folders are stored on your computer, and develop good habits for keeping your file system organised.

The File System

The structure of the file system is referred to as a tree. Starting with a root folder at the top, it branches downward into subfolders, which can contain more subfolders, and so on. Here is a tree representation of the same file system shown in the file explorer above.

The most important thing to understand is that every file has a unique location in the file system. So while there are two files called survey_data.csv in the example above, they are not the same file! This has two important implications for data management.

  • Firstly, you need to understand how your computer refers to unique files and folders by their path. This enables you to write analysis scripts that can read and write files without relying on the file explorer, which improves reproducibility and makes it easier to work in teams. We cover this in the next section.
  • Secondly, you need to organise your files system properly, so that you don’t lose track of where data is stored. This is especially important when working with sensitive data, which comes with legal and ethical responsibilities to keep it safe and delete it when you’re done with it. In our example above, we show a common, sloppy procedure: someone downloads survey_data.csv into their Downloads folder, and then copies it into their project folder. This leaves a useless copy of sensitive data in the Downloads folder, where it’s likely to be forgotten and left there indefinitely.

Absolute file paths

The two versions of survey_data.csv above are in different locations, and your computer needs to know which one you mean when you refer to it. To uniquely identify these files, you can specify their asbolute path: the chain of folders you need to follow from the root of the tree to that file. The two files above have the following paths:

/Users/Chris/Projects/master_thesis/survey_data.csv
/Users/Chris/Downloads/data/survey_data.csv

In Windows this works the same way, but the slashes are reversed and the root of the tree is a drive letter:

C:\Users\Chris\Projects\master_thesis\survey_data.csv
C:\Users\Chris\Downloads\data\survey_data.csv
NoteHow do I find a file’s absolute path?

You can use your file explorer to find a file’s absolute path, and copy it into your analysis script.

  • macOS (Finder): select the file, then press Cmd + Option + C to copy its path, or right-click while holding Option for a “Copy as Pathname” option.
  • Windows (File Explorer): hold Shift and right-click the file, then choose “Copy as path”.

We’ll also show a couple of handy RStudio-specific tricks for this later in the book.

An absolute path specifies the EXACT location of the file. However, this has two drawbacks:

  • It’s long to type, and easy to get wrong.
  • It’s tied to one specific computer and user. If our example user Chris sends their analysis script to a colleague, the absolute path C:\Users\Chris\Projects\master_thesis\survey_data.csv will not exist on the colleague’s computer, and the script will fail.

This is why you should almost always use relative paths instead of absolute ones.

Relative paths and working directories

A relative path describes a file’s location relative to the current working directory. For example, if the working directory is /Users/Chris/Projects, the relative path to survey_data.csv is:

master_thesis/survey_data.csv

To see how this works, scroll up to the tree diagram and imagine that your computer is “standing” in the Projects folder. From there, you simply follow the chain of folders down to the file you want.

Analysis software like R allows you make any folder the working directory. We’ll show you how to do this later when we introduce RStudio, which makes this very easy. The general recommendation is to set the working directory to the folder of a project you’re working in, like /Users/Chris/Projects/master_thesis. This has two great benefits:

  • You can directly read and write files in that project folder, using only the file name.
  • You can move the whole project folder to a different computer. Since the paths are relative to that folder, all the scripts will still work. This is great for reproducibility and collaboration.

1.1.2 File types and extensions

The short suffix after the dot in a file name — the file extension — tells your computer (and you) what kind of file it is, and which program should open it. Many file explorers hide extensions by default; it’s worth turning this setting on, since in this course the difference between file types genuinely matters.

Some of the extensions you’ll run into most often in this book:

Extension What it is
.csv Comma-separated values: a plain-text table, one row per line, values separated by commas. The most common format for exchanging data.
.xlsx / .xls An Excel spreadsheet (a “workbook”). Looks similar to a .csv when opened, but is stored in a more complex, non-plain-text format that can also hold formulas, formatting, and multiple sheets.
.txt A plain-text file: just characters, no formatting.
.r / .R An R script: plain text containing R code.
.json A structured, plain-text format often used to exchange data between programs (you’ll encounter this if you ever work with APIs).
.pdf A fixed-layout document, for reading, not editing.
.docx A Microsoft Word document.
.zip A compressed archive bundling multiple files together — covered next.

1.1.3 Zip files

A zip file (extension .zip) is an archive: a single file that contains, and compresses, a whole bundle of other files and folders. Zip files are everywhere once you start downloading course materials or datasets, for two reasons: they let you download many files in one go, and compression makes the download smaller.

The reasons we single them out here, is that you need to know how to handle them properly. A common mistake is that people double click it like a normal folder. This will show you the contents, but the files inside are still “inside” the zip file, and most programs won’t be able to read them until you extract (or “unzip”) them.

On both Windows and macOS, this is usually as simple as right-clicking the .zip file and choosing “Extract All…” or “Extract”. Depending on what you choose, it either need to specify where to extract the files to, or it will extract them to the same folder as the zip file itself.

An example of this is shown in the file tree above. Inside the Downloads folder, there is a zip file called data.zip, and the data folder represents the contents of that zip file after extraction. This also reveals another data sensitivity pitfall: if the survey_data.csv file came out of the zip file, it means that it’s now actually stored in three places: the data.zip file, the extracted data folder, and the copy in the master_thesis folder.

1.1.4 A few general habits worth having

A handful of general-purpose keyboard shortcuts are worth building into muscle memory, since you’ll use them constantly in almost any program you work with in this course:

Shortcut (Win/Linux) Shortcut (macOS) What it does
Ctrl + s Cmd + s Save the current file
Ctrl + C / Ctrl + V Cmd + C / Cmd + V Copy / paste
Ctrl + F Cmd + F Find (and replace) text in a document
Ctrl + z Cmd + z Undo your last change
Ctrl + y Cmd + y Redo your last undone change
Ctrl + shift + z Cmd + shift + z Redo your last undone change (alternative)

Two more habits that will save you a lot of trouble down the line:

  • Save your work often, and give files short, descriptive names (e.g. week1_notes.txt rather than Untitled2).
  • Know where your “Downloads” folder is, and get into the habit of moving files out of it into the right course folder soon after downloading them — it’s the single most common place where “lost” files end up.

With these basics in place, you’re ready to start exploring how specific tools — starting with R — organise and work with data.
