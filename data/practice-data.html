Practice Data

A simulated newspaper-trust survey used across most of the book’s statistics chapters.

NoteDataset status

Status: migrated (generated at build time from data/simulation_scripts/newspaper_trust.r; the repo contains only the simulation script, not the CSV itself — see Data Standard) Access: read_csv("https://dev.dataliteracy.cc/practice_data.csv")

What this dataset is for

A simulated survey (n = 600) about whether watching a short film about journalism changes people’s trust in journalists. Respondents were randomly assigned to one of three groups (control, negative, positive), and trust in journalists was measured before (trust_t1) and after (trust_t2) the film. It’s the book’s main “practice” dataset: the same variables are reused from Data Frames all the way through Regression and Linear Model Assumptions, so students see one dataset grow more familiar across chapters instead of a new unexplained one each time.

Columns

Column Type Description
id integer Respondent ID, 1–600.
age integer Age in years, 18–65.
political_orientation character Self-reported political orientation: "left", "center", or "right".
political_interest numeric Self-reported political interest, rescaled to a 1–7 scale.
np_subscription character Whether the respondent has a newspaper subscription: "no" or "yes". Simulated to be more likely at higher ages.
news consumption integer Average hours of news consumption per week. Note the literal space in this column name (not an underscore) — deliberate, see Caveats below.
experiment_group character Random assignment: "control", "negative", or "positive" (which framing of journalism the respondent saw).
trust_t1 numeric Trust in journalists before the intervention, 1–10 scale. Reconstructed as the mean of the aligned trust_t1_item1/3/4/5 items.
trust_t2 numeric Trust in journalists after the intervention, 1–10 scale. Lower in the negative group (especially for non-subscribers), slightly higher in positive, unchanged in control.
trust_t1_item1…trust_t1_item5 integer The 5 individual survey items (1–10) underlying trust_t1. item3 is reverse-coded in the raw file.
trust_t2_item1…trust_t2_item5 integer The 5 individual survey items (1–10) underlying trust_t2. item3 is reverse-coded in the raw file.

Simulation notes

Generated by data/simulation_scripts/newspaper_trust.r, with set.seed(1). Deliberately built-in relationships, useful as teaching “answers” when checking a model’s output:

  • trust_t2 is significantly lower than trust_t1 in the negative group (an ANOVA/t-test contrast), and that drop is smaller for newspaper subscribers (an interaction).
  • subscription likelihood increases with age (logistic relationship) and newspaper subscribers report higher news consumption, but with less variance than non-subscribers — handy for illustrating Levene’s test.
  • The 5 items behind trust_t1/trust_t2 were simulated with different loadings/noise per item (so they’re suitable for a reliability/scale-construction exercise), then the scale score was reconstructed from items 1, 3, 4, 5 only (item 2 deliberately loads more weakly and is excluded from the “official” scale in the simulation).

The script also deliberately injects some messy values — a handful of odd age entries and the news consumption column name — on purpose, as material for the Data Cleaning chapter. See Caveats below.

Caveats

  • The news consumption column name contains a literal space, not an underscore like every other column, and the handful of age values that look like birth years (e.g. 1987) rather than ages are intentional, not bugs — they exist specifically so the Data Cleaning chapter has real messiness to demonstrate fixing. Don’t “clean” these in the simulation script itself.
  • np_subscription and experiment_group are plain character columns rather than factors in the raw CSV.
  • Planned follow-up: split this single script into several smaller, single-purpose simulated datasets (e.g. a clean general-purpose dataset plus a dedicated, deliberately-messy dataset just for the Data Cleaning chapter), instead of combining both purposes in one file as it is now.
